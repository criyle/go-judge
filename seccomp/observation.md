# Compiler syscall observation

This observation records a cold-cache syscall trace of the compiler and runtime commands configured in `go-judge-demo/src/constants/languageConfig.ts`.

## Method

- Environment: x86 host.
- Tracing: `strace -f -qq`, including child processes.
- Coverage: 16 language configurations, with compilation and execution traced separately (32 commands total).
- Result: all commands exited with status 0.
- The lists below contain syscall names only; they do not capture argument values, paths, frequency, or denied attempts.

## Findings

- `io_uring_setup` and `io_uring_enter` were observed in Node.js and TypeScript workloads. They are absent from Moby's x86_64 allow policy. Node.js uses libuv, which falls back to its threadpool for asynchronous filesystem operations when io_uring is unavailable; Linux network polling continues to use epoll.
- `clone3` was observed by several toolchains. Moby intentionally denies it with `ENOSYS`, allowing runtimes to fall back to `clone`.
- `arch_prctl` is allowed by Moby for amd64 and was observed throughout the corpus.
- `socket` was observed by Java. Name-only tracing cannot determine the socket domain; the policy's argument rules remain necessary to block AF_ALG/copyfail.

## Benchmark record

These results use the integration benchmark `BenchmarkGoJudge_Concurrency` with
`/bin/true`, HTTP requests over a persistent connection, 30 seconds per
parallelism level, and parallelism 1, 2, 4, and 8. Each level was run as a
separate benchmark after a fresh service restart. Values are `ns/op`; the
server ran on an x86 host.

| Configuration | P1 | P2 | P4 | P8 |
|---|---:|---:|---:|---:|
| Per-child `-no-seccomp` baseline | 1,489,518 | 944,656 | 781,366 | 747,779 |
| Per-child seccomp installation | 1,581,888 | 947,085 | 719,804 | 775,566 |
| Init-installed `-no-seccomp` baseline | 1,548,070 | 935,285 | 758,367 | 739,841 |
| Init-installed seccomp; children inherit it | 1,575,266 | 905,942 | 759,120 | 732,917 |

The paired comparisons remain small and variable. Per-child seccomp changed
latency by approximately +6.2%, +0.3%, -7.9%, and +3.7% relative to its own
baseline at P1/P2/P4/P8. Init-installed seccomp changed latency by
approximately +1.8%, -3.1%, +0.1%, and -0.9% relative to its own baseline.
These results do not establish a consistent end-to-end speedup, but the
init-installed design has the smaller and more stable overhead in this round.

Earlier syscall-focused tracing was performed with `strace -f -c` on the same
kind of x86 host. The per-child configuration recorded approximately 1,058
seccomp calls and 0.204 seconds in `seccomp`; the no-seccomp control recorded no
seccomp calls. Those numbers include tracing overhead and are not wall-clock
latency measurements.
